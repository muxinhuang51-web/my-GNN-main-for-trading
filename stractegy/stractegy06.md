# 稳定主题簇 + 日频微调 执行计划

## 1. 核心目标

上一版已经验证了一个重要方向：直接做个股预测不稳定，但把 GNN embedding 聚合成簇以后，簇级轮动有更好的收益表现。下一阶段的目标不是马上加风险控制，而是先把模型训练机制想清楚，升级成更接近真实市场结构的版本：

```text
GNN 表示模型 = 慢变量
主题簇结构 = 中变量
簇收益预测器 = 快变量
```

具体来说：

- GNN 不每天大幅重训，避免 embedding 空间每天漂移。
- 主题簇不每天重新生成，改成月度或季度更新。
- 簇收益预测器每天微调，用最新历史窗口适应短期市场风格。

## 2. 当前版本的问题

当前 `backtest_cluster.py` 已经实现了固定 GNN + 每日训练簇预测器的第一版链路，但还有几个结构性问题：

1. 每天重新 KMeans，导致今天的 cluster 3 和明天的 cluster 3 没有连续含义。
2. 簇更像临时相似股票集合，还不是稳定主题。
3. GNN embedding 模型全程固定，如果市场风格变化，底层表示可能无法适应。
4. 每天从零训练簇收益预测器，不能继承前一日已经学到的参数。
5. 输出的簇画像不足，难以判断模型到底在轮动行业、概念、风格还是噪声。

下一版优先解决模型训练和主题稳定性问题，风险控制暂时后置。

## 3. 新训练框架

### 3.1 月度或季度更新主题簇

在每个月初或每个季度初，重新定义一次市场主题结构。

执行流程：

1. 使用截至更新日前一交易日的数据构造图。
2. 加载或微调 GNN embedding 模型。
3. 提取全股票池 embedding。
4. 用 KMeans 或其他聚类方法生成主题簇。
5. 保存本期簇中心、股票归属和簇画像。

输出文件建议：

- `outputs/topic_periods/topic_clusters_YYYYMM.csv`
- `outputs/topic_periods/topic_centers_YYYYMM.npy`
- `outputs/topic_periods/topic_profile_YYYYMM.csv`
- `outputs/topic_periods/topic_metadata_YYYYMM.json`

主题簇文件至少包含：

- `period`
- `trade_date`
- `ts_code`
- `cluster_id`
- `industry`
- `concept`
- `cluster_size`

### 3.2 每日微调簇收益预测器

每天回测时，不重新定义主题，只基于当前所在周期的固定主题簇做预测。

执行流程：

1. 找到当前交易日对应的主题周期。
2. 使用固定的 `stock -> cluster_id` 归属。
3. 用过去 `train_window` 天构造簇级训练样本。
4. 从前一日的簇预测器参数继续训练少量 epoch。
5. 预测当前日每个主题簇的预期收益。
6. 选择 Top-K 主题簇进入组合。

关键变化：

- 不再每天从零初始化 `ClusterReturnPredictor`。
- 每天只做轻量微调。
- 学习率建议从 `1e-4` 或 `5e-5` 开始。
- 每日微调 epoch 建议先设为 `1` 到 `5`。

### 3.3 GNN 的更新节奏

GNN 是底层表示模型，不建议一开始每天微调整个 GNN。

推荐先做三档实验：

| 版本 | GNN 更新 | 主题更新 | 簇预测器更新 | 目的 |
|------|----------|----------|--------------|------|
| A | 固定 `best_model.pt` | 月度 | 每日微调 | 验证稳定主题是否优于每日 KMeans |
| B | 月度微调 GNN | 月度 | 每日微调 | 验证 GNN 慢更新是否提升收益 |
| C | 季度微调 GNN | 季度 | 每日微调 | 验证更慢主题周期是否更稳定 |

第一优先级做 A，不要一开始同时改 GNN 和聚类。

## 4. 回测逻辑改造

当前回测是：

```text
每日构图 -> 每日 embedding -> 每日 KMeans -> 每日训练预测器 -> 选 Top-K 簇
```

下一版改成：

```text
月度/季度更新日：
  生成主题簇
  保存主题归属和簇画像

普通交易日：
  读取当前周期主题簇
  构造当前日簇特征
  继承昨日预测器参数
  用历史窗口微调
  预测主题簇收益
  选 Top-K 主题
  计算组合收益
```

这样做的好处是：

- 簇 ID 有连续含义。
- 可以观察主题的生命周期。
- 可以分析某个主题连续被选中的原因。
- 模型训练从“每天重来”变成“逐日适应”。

## 6. 每日训练样本定义

对于某个交易日 `t`，训练样本只允许使用 `t` 之前的信息。

推荐定义：

```text
特征日：i 的历史窗口 [i - lookback, i)
标签日：i 的真实收益 returns[i]
训练区间：[t - train_window, t)
预测日：t
```

对于每个历史训练日 `i`：

1. 用 `i` 之前的历史窗口构造股票特征和图。
2. 提取股票 embedding。
3. 使用当前主题周期固定的股票归属。
4. 对每个主题簇做 embedding 均值池化。
5. 用簇内股票在 `i` 当天的平均收益作为标签。

注意：

- 聚类生成不能使用标签收益。
- 预测日 `t` 的收益不能出现在训练里。
- 主题周期的生成日期必须早于该周期内所有回测日期。

## 7. 验收指标

第一阶段先看模型结构是否跑通，不急着追求收益最高。

必须输出：

- 每日收益
- 累计收益
- 最大回撤
- Sharpe
- 等权基准对比
- 超额收益
- 每日选中主题
- 每日主题预测收益
- 每日簇预测 IC
- 每日选股数量

重点观察：

1. 固定主题后，选股数量是否比每日 KMeans 更稳定。
2. 主题是否具有可解释性。
3. 每日微调是否比每日从零训练更稳定。
4. 月度主题和季度主题哪个回撤更小。
5. 主题轮动是否集中在少数几个强主题，而不是随机跳动。

## 8. 实验顺序

### 实验 1：固定 GNN + 月度主题 + 每日从零训练

目的：只验证主题固定是否有效。

这是最小改动版本：

- GNN 仍用 `best_model.pt`
- 每月生成一次主题簇
- 簇预测器仍然每天从零训练

如果这个版本已经优于当前每日 KMeans，说明稳定主题本身有价值。

### 实验 2：固定 GNN + 月度主题 + 每日微调

目的：验证每日继承模型参数是否提升稳定性。

改动：

- 第一天初始化 `ClusterReturnPredictor`
- 后续交易日从昨日 checkpoint 继续训练
- 每天训练少量 epoch

### 实验 3：月度微调 GNN + 月度主题 + 每日微调

目的：验证底层 embedding 慢更新是否能缓解后期风格变化。

注意：

- GNN 微调只能使用更新日前的数据。
- 每月微调后重新生成主题簇。
- 需要保存每个月的 GNN checkpoint。

### 实验 4：季度主题版本

目的：观察更慢主题更新是否降低换手和回撤。

对比：

- 月度主题收益更灵敏
- 季度主题更稳定
- 如果季度效果更好，说明主题结构不应该太频繁重建

## 9. 暂不做的事情

为了避免实验变量太多，以下内容先不做：

- 止损
- 仓位择时
- 行业中性
- 交易成本优化
- 簇内二次选股
- 做空组合
- 复杂注意力模型

这些都等模型训练机制验证清楚以后再加。

## 10. 第一版代码改造清单

1. 增加主题周期生成函数。
2. 增加主题簇保存和加载。
3. 修改回测逻辑，使用固定周期主题而不是每日 KMeans。
4. 增加每日预测器 checkpoint。
5. 增加每日微调模式。
6. 输出 `selected_topics.csv`，记录每天选中的主题。
7. 输出主题画像，方便人工判断簇是否像真实主题。
8. 重新绘制回测图，加入主题选中频率和基准对比。

## 11. 最小可执行版本

第一版只需要实现：

```text
固定 best_model.pt
月度生成主题簇
每日从零训练簇预测器
输出主题回测结果
```

验收标准：

- 能完整跑完当前 2026-02 到 2026-05 区间。
- 每个交易日都能映射到一个主题周期。
- 每日选中主题能落盘。
- 回测结果能和当前 `outputs/cluster_backtest/daily_returns.csv` 对比。

如果第一版没有明显退化，再进入每日微调版本。

## 12. 关键判断

这个阶段最重要的问题不是“收益最高是多少”，而是回答三个模型问题：

1. 稳定主题是否比每日临时聚类更好？
2. 每日微调是否比每日从零训练更好？
3. GNN 慢更新是否能降低后期风格切换带来的回撤？

只要这三个问题回答清楚，后面再加风险控制、仓位管理和交易成本，策略就会更像一个真正的主题轮动系统。
