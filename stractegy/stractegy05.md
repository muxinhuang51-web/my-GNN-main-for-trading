# 图嵌入聚类 + 簇间轮动预测 执行文档

## 1. 目标

把现有的个股级 GNN 代码扩展成一条可以直接执行的链路：图表示、动态聚类、簇收益预测、回测验证。第一优先级不是做新数据管道，而是复用当前仓库里已经存在的数据、模型和 notebook，让 AI 按照文档就能一步步跑下去，不需要猜文件名、接口和中间产物。

## 2. 现有资产映射

### 2.1 已有数据

- data/stock_pool_all.csv：股票池
- data/node_feats_allx10.csv 和 data/node_feats_allx10.npy：节点特征
- data/industry_mapping.csv：行业映射
- data/daily_returns.csv：历史日收益率
- data/hetero_edges.pt：现成异构图边
- data/train_graph.pt 和 data/val_graph.pt：训练和验证图样本
- feature_config.json：特征配置
- best_model.pt：现成训练好的模型权重

### 2.2 已有代码入口

- main02.ipynb：已有 build_hetero_graph()，负责构建和保存异构图
- main04.ipynb：已有 run_backtest()、evaluate_performance()、export_feedback()，负责回测和结果导出

### 2.3 当前 baseline

第一版必须保留现有个股级回测链路作为 baseline，再在其上增加簇级中间层。这样做的目的只有三个：

- 先验证数据是否能正常流通
- 方便和旧方案直接对比
- 簇级方案如果不稳定，仍然能回退到现有流程

## 3. 先验约束

1. 只使用当前时点之前的信息，不能把未来数据混进聚类或特征构造。
2. 新增模块必须复用现有数据文件路径，不要让 AI 再去找一套新的 CSV。
3. 每一步都要输出可检查的中间结果，至少包含 shape、样本数和日期范围。
4. 先跑通单日，再跑短区间，最后再扩展到全区间。
5. 第一版不要同时改训练、特征、图构造和回测四件事，先只改表示和聚类层。

## 4. 推荐执行链路

已有数据文件 → 复用现有图构造和模型加载 → 提取股票嵌入 → KMeans 生成动态功能簇 → 计算簇画像和簇收益标签 → 训练簇级预测器 → 输出 Top-K 簇 → 复用现有回测框架做验证

这条链路的核心不是做一个更复杂的模型，而是把现有模型的个股表示，重新组织成更少、更稳、更容易解释的预测对象。

## 5. 实施步骤

### 5.1 第一步：让现有模型支持导出嵌入

目标不是重写模型，而是让 current best_model.pt 对应的网络在前向时可以返回中间层表示。

执行要求：

- 如果现有模型类已经有倒数第二层，就直接加一个返回嵌入的开关。
- 如果没有，就在不破坏原输出的前提下增加一个 forward 的可选参数。
- 输出张量必须是 [N, emb_dim]，其中 N 是股票数。

验收标准：

- 单日输入能返回 embedding
- embedding 的股票顺序必须和 stock_codes 完全一致
- 先打印 embeddings.shape 和前 5 个股票代码，确认对齐无误

建议新增文件：

- models/embedding_model.py

### 5.2 第二步：基于嵌入做聚类和簇画像

目标是把每日股票嵌入压缩成少量簇，并给每个簇打上可读标签。

执行要求：

1. 取某一个交易日的截面数据，生成股票嵌入。
2. 用 KMeans 做聚类，初始簇数设为 20。
3. 对每个簇统计以下内容：
   - 簇内股票数量
   - 平均原始特征
   - 主要行业
   - 主要概念
   - 簇内平均下日收益
4. 保存成一个可读表格，供后续命名和分析。

验收标准：

- 每个簇至少能输出 size、行业占比、均值特征
- 若出现空簇，要在日志中明确记录，不允许静默忽略
- 簇画像文件必须落盘

建议新增文件：

- cluster_profile.csv

### 5.3 第三步：训练簇级预测器

核心思想是先在簇空间做预测，再把簇预测映射回股票。

执行要求：

- 输入：股票嵌入和簇标签
- 过程：对每个簇做平均池化，得到簇表征
- 输出：每个簇的下一交易日预期收益
- 标签：用簇内股票下日真实收益的均值

训练时先用最简单的 MLP，不要一开始就加注意力、时序模块或者更复杂的图结构。

验收标准：

- 训练损失能下降
- 验证集上至少能输出簇级 IC
- 簇级预测结果能排序，且不报 shape 错误

建议新增文件：

- models/cluster_predictor.py

### 5.4 第四步：接入回测

这里不要重写回测引擎，优先复用 main04.ipynb 里的 run_backtest() 框架。

执行要求：

- 在每个交易日先构建当日图
- 导出股票嵌入
- 聚类得到簇标签
- 簇预测器输出 Top-K 簇
- 将 Top-K 簇内股票转成选股列表
- 使用现有的 compute_portfolio_return() 和 run_backtest() 逻辑计算收益

第一版建议只做多，不做空，不做行业中性，不做复杂约束。

验收标准：

- 回测能跑完整个样本区间
- 每天都能输出当日选中的簇和股票数量
- 最终能生成 daily_returns.csv 和 metrics.json

建议新增文件：

- backtest_cluster.py

### 5.5 第五步：结果对比

至少保留三组结果：

- 现有个股级 baseline
- 簇级预测版
- 簇级预测版加简单过滤规则后的版本

对比指标至少包含：

- 年化收益率
- 夏普比率
- 最大回撤
- 日度 IC 或簇级 IC
- 选股覆盖数

建议输出：

- comparison_report.md

## 6. 推荐的文件分工

- main02.ipynb：继续负责图构造和数据准备，不要把新逻辑全部塞进去
- main04.ipynb：继续负责回测骨架和绩效输出
- models/embedding_model.py：只负责嵌入导出
- models/cluster_predictor.py：只负责簇收益预测
- backtest_cluster.py：只负责簇版回测编排

这样拆分的好处是：AI 更容易定位问题，人也更容易逐步验收。

## 7. AI 执行清单

每次改动都按这个顺序来：

1. 先确认输入文件存在且路径正确
2. 先打印张量 shape 和日期范围
3. 先在单日样本上跑通
4. 再扩到短区间
5. 最后才跑全区间
6. 每一步都保留一个中间输出文件，便于复查

如果 AI 发现以下情况，要立刻停下来检查，而不是继续硬跑：

- 股票顺序对不上
- 某天簇全空
- 簇标签里出现异常值
- 回测每天选股数波动极大
- 指标全是 NaN
